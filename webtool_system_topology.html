推荐的 9 步使用流程 — 从地址搜索到投资决策
1
输入目标地址 → 锁定地块
在 Site Investigation 面板顶部搜索框输入完整地址（如 "12 Smith St, Melbourne VIC 3000"）。系统自动调用 OSM Nominatim geocoding，获取 lat/lon，随后通过 4 级级联（OSM by ID → OSM Cadastral → Vicmap WFS → OSM Containing）拉取官方地块边界、面积、正面宽、深度、高程数据。
terrain_engine Vicmap WFS 卫星地图自动定位
2
上传 VicPlan / S32 / 测量报告
点击 "上传文档" 区域，可同时上传 VicPlan PDF（规划信息）、Section 32（产权文件）、Survey Plan（测量报告）三类文档。系统自动提取：分区代码、overlay 标志、单一住宅契约、S.173 协议、权属登记号（dealing numbers）、地役权宽度、服务供应情况。
pdf_ocr ai_adapter parsers.js Section 32 段落感知
3
确认并应用提取结果
文档解析完成后，面板显示 "已提取字段预览"，绿色 ✅ 字段为自动填充。点击 "Apply" 按钮将数据批量写入 Store（priority: VicPlan < S32 < Survey，后者覆盖前者）。自动估算字段带 "EST" 标记，可随时手动覆盖。左侧边栏置信度评分实时更新。
batchDispatch confidence_engine ConfidenceCard
4
Physical Conditions — 确认地形成本
切换至 "Physical Conditions" 面板，检查自动填入的坡度（slope）、朝向（aspect）、高程差，以及自动估算的场地准备费用（Site Works Cost）。如有特殊情况（护坡墙、土壤问题）可手动覆盖，勾选 Lock 图标固定该字段不被后续计算覆盖。
PhysicalConditionPanel financeLocks
5
Planning & Zoning — 核查规划限制
切换至 "Planning & Zoning"，在 "Auto-Extracted from Document" 区域检查：分区代码（如 GRZ1、NRZ）、所有 overlay（HO、DDO、SBO）、单一住宅契约（🔒）、S.173 协议（📋）、权属 dealing numbers（如 D151733）。Compliance 面板自动显示该分区的最大高度、覆盖率、退界要求。
PlanningPanel zoning_rules risk_engine
6
Market Intelligence — 输入 GRV
在 "Market Intelligence" 面板，输入每套预售价（GRV Per Unit）和开发单位数（Units），以及参考销售周期（DOM）。系统自动计算总 GRV，并连接至财务计算引擎。可参考右侧 ABS 数据指标作为基准。
MarketPanel_V2 market.grvPerUnit
7
Financial Analysis — 完善财务参数
在 "Financial Analysis" 面板核对：土地价格、建筑面积（可 Lock 防止覆盖）、建造成本/㎡、法律费用、应急备用金比例（%）、项目周期（月）、目标利润率（Target Margin %，影响 Sovereign Memo 的 PROCEED/RENEGOTIATE 判断）。印花税自动计算（海外买家 + OTP 勾选）。
FinancePanel tax_engine live_calc_engine irr_engine
8
AI Insights — 敏感性分析 & 风险评估
切换至 "AI Insights"。页面顶部自动显示：True IRR（年化，Newton-Raphson）、开发利润率、资本化利息。5×5 敏感性热力矩阵实时展示 GRV ±10% × 建造成本 ±10% 的利润率变化（绿≥20%、黄12-20%、橙0-12%、红亏损）。点击 "Generate Insights" 获得基于 Melbourne 行业阈值的规则推导风险报告。
InsightPanel sensitivity_engine insight_engine
9
Sovereign Memo — 最终投资决策
切换至 "Sovereign Memo"，系统生成一份完整的执行备忘录：项目 ID、地块信息摘要、风险条款清单（Trust Layers）、收益瀑布图（Yield Waterfall）、最终判决（PROCEED 🟢 / RENEGOTIATE 🔴）。判决基于 实际利润率 vs 目标利润率（Financial Analysis 中设置的 Target Margin %）。可导出为 PDF 或 Obsidian MD。
SovereignMemoPanel export_engine computeLiveSnapshot()
系统共 40+ 个 domain 模块，按功能分域。
📐 Spatial 空间域
terrain_engine
地址→地块，4级级联：OSM ID → OSM Cadastral → Vicmap WFS → OSM Containing。坡度、高程、面积推导。
location_engine
POI 评分：学校（公私立区分）、火车站、电车、超市、咖啡馆、医院。返回 0-100 位置分。
confidence_engine
6 个数据支柱评分：地址坐标、尺寸、规划区、市场GRV、财务输入、文件智能。
constraint_engine
从 investigation.facts[] 触发成本/风险动作（COST/RISK/BLOCK）。
risk_engine
Overlay 风险评级（HO/DDO/SBO/BMO/VPO），ZSB ResCode 检查。
synthesis_engine
综合地形+规划+位置数据，生成人类可读的场地分析摘要。
parcel_engine
地块尺寸推导：bounding box 旋转（2°步长），最小矩形面积法估算正面宽/深度。
geo_utils
Haversine 距离计算、经纬度边界框、坐标转换工具集。
💰 Finance 财务域
live_calc_engine
实时快照：TDC、GRV、profit、margin、IRR、capInterest。防抖 300ms，模块级 _prev 防 HMR。
irr_engine
Newton-Raphson IRR（60次迭代），buildIRRCashFlows S 曲线现金流分布，年化 IRR 输出。
sensitivity_engine
5×5 利润矩阵：GRV ×Cost ±10%，NaN/Infinity 守卫，margin = profit/GRV。
cashflow_engine
Sigmoid S 曲线建造成本月度分布（steepness=0.7），权重归一化。
tax_engine
维多利亚印花税（累进税率），海外买家附加税（8%），OTP 优惠处理，GST 计算。
comparison_engine
多场景策略矩阵，4类预设原型（dual_occ/townhouse/apartments/custom）。
cost_engine
场地准备成本（坡度→费用查表），overlay 触发成本叠加。
insight_engine
规则推导风险报告：margin 阈值、IRR 阈值、overlay 组合，输出 riskLevel/recommendation。
📄 Extraction 文件解析域
ai_adapter
Section 32 段落感知解析：ENCUMBRANCES 段落提取 → dealing numbers 正则 → 单一住宅契约 10 种变体。
unified_engine
FIELD_TO_PATH 映射表（50+字段），normalizeVicPlanResult / normalizeS32Result，priority merge。
parsers.js
专项解析：lotM 地块编号、easement 地役权宽度、S.173 条款细节、mortgage 抵押权。
pdf_ocr
extractFileText()：ArrayBuffer → pdf.js → 逐页文本拼接，返回完整文档字符串。
🔍 Audit 审计域
consistency_auditor
防抖 800ms，检测数据逻辑冲突（如 NRZ 但 units>1），写入 system.consistencyConflicts。
sanity_validator
异常值检测：landPrice/buildCostPSM/margin/IRR 超出行业阈值（含百分比表达修正）。
data_merger
多源数据合并策略，confidence 加权优先级处理。
sovereign_orchestrator
整合 risk + consistency + sanity 结果，生成 SovereignMemoPanel 的 trustLayers[]。

// 当前（弱）： const res = await fetch('https://nominatim.openstreetmap.org/search?q=...') // 替换为（强）：MapShare VIC 官方 geocoder const MAPSHARE_URL = 'https://api.mapshare.vic.gov.au/arcgis/rest/services' + '/mapshare/Geocoding/GeocodeServer/findAddressCandidates'; async function geocodeAddress(query) { // 1️⃣ MapShare VIC — GNAF + Vicmap Address（无需 key） try { const url = MAPSHARE_URL + '?SingleLine=' + encodeURIComponent(query) + '&maxLocations=5&outFields=*&f=json'; const r = await fetch(url, { signal: AbortSignal.timeout(8000) }); const d = await r.json(); if (d.candidates?.length) { const best = d.candidates[0]; return { lat: best.location.y, lon: best.location.x, display: best.address, score: best.score }; } } catch(_) {} // 2️⃣ Nominatim fallback const r2 = await fetch('https://nominatim.openstreetmap.org/search?q=' + encodeURIComponent(query) + '&format=json&countrycodes=au&limit=3'); const d2 = await r2.json(); if (d2[0]) return { lat: +d2[0].lat, lon: +d2[0].lon, display: d2[0].display_name }; return null; }
MapShare VIC 优势
✓ 使用 GNAF（国家地址文件）+ Vicmap Address
✓ 每月由 DEECA 官方更新
✓ 无 API Key，无请求限制
✓ 对维多利亚新建楼盘、细分地块精度最高
✓ 返回置信度评分（score 0-100）
补充建议（不用改代码）
• 上传 Survey Plan PDF → 自动覆盖面积/正面宽
• 正面宽/深度字段设 Lock 锁定防止被覆盖
• 用左侧 "Verify on property.com.au" 链接验证
• 置信度评分 <55% → 优先补充文件上传
• 上传 VicPlan PDF → 规划信息 100% 准确
🤔 为何 Vicmap WFS（第二阶段）已经很准但地块数据仍有问题？
第二阶段（Vicmap WFS）的地块 边界精度 非常高——它是维多利亚官方地籍数据。
但 bounding box 旋转法 推导正面宽/深度在非矩形或斜向地块上会有 5–15% 误差。

真正影响所有下游计算的根源：如果第一阶段 Nominatim 返回的坐标偏移超过 20m，Vicmap WFS 的 CONTAINS 查询就会落到邻近错误地块上，导致面积、分区、规划信息全部出错。

一劳永逸的结论：把第一阶段换成 MapShare VIC Geocoder，坐标精度提升到 <5m 级别（GNAF），Vicmap WFS 的 CONTAINS 查询成功率接近 100%，整条管道精度根本性提升，无需任何 API key，完全免费，长期有效。
